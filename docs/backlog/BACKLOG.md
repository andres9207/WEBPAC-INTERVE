## Fundación

Bloque transversal y prerrequisito. Los ADR 0001, 0013, 0014, 0026 y 0027 declaran que ninguna parte del CORE debe construirse antes de que exista autorización en el servidor, migraciones versionadas y una utilidad central de transacción.

## Taxonomía aplicada

**Base de datos** — crear tabla, crear columna, modificar columna, crear FK, crear índice, crear UNIQUE, crear migración, migrar datos existentes, validar integridad, revisar impacto de índices, revisar rendimiento.

No se incluyen tareas de **procedimiento, función ni trigger** de base de datos: es una decisión explícita de los ADR, no un olvido. ADR-0013 decisión 8 fija que la bitácora se escribe desde la capa de servicio y no mediante disparadores, porque el servicio conoce el usuario de la sesión y el contexto de negocio y un disparador no. ADR-0002 declara que no se introducen vistas ni procedimientos. Las funciones de cálculo viven en el módulo de backend versionado de ADR-0026.

**Backend** — endpoint, controller, service, query SQL, validaciones, reglas de negocio, manejo de errores, transacciones, permisos, auditoría, logs, respuestas HTTP, manejo de concurrencia.

El proyecto no usa capa de repository o DAO: los módulos siguen la tríada `routes` / `controller` / `service`, con el acceso a datos dentro del servicio a través de `executeQuery`. Las tareas respetan esa estructura en lugar de imponer una capa nueva.
